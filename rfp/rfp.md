# **1. 프로젝트 개요**

공유 전동킥보드에 부착되는 IoT 안전발판이 다인탑승을 감지하면, 기기 QR ID와 감지 시각 데이터를 서버로 전송합니다. 본 프로젝트는 이 데이터를 수신·저장하고, 관리자가 웹 대시보드에서 조회·검색·리포트 출력할 수 있는 시스템을 구축하는 것을 목적으로 합니다.

현재는 약 50대 규모의 필드테스트(파일럿) 검증 단계이나, 검증 이후 실제 사업으로 확장 운영할 계획이므로, 향후 기기 수량 및 트래픽 증가에 유연하게 대응 가능한 구조로 설계되어야 합니다.

# **2. 데이터 흐름**

**기기(안전발판) → API(서버) → 데이터베이스 저장 → 관리자 웹 대시보드에서 조회**

※ 위치정보(GPS) 전송여부는 결정되지 않았으나 일단 프로토콜 상에는 들어가고 추 후 사용 여부를 판단할 예정입니다.

# **3. 기기 전송 데이터 규격 (예시)**

{  
 "device\_id": "PAD-0001",  
 "event\_time": "2026-09-11T14:32:10+09:00",

"gpsData": " ",

"received\_at": " ",

"battery\_level": 82  
}

| **필드명** | **설명** |
| --- | --- |
| device\_id | 발판별 고유 QR ID |
| event\_time | 다인탑승 감지 시각 (기기 RTC 기준, 초 단위) — 경찰 제출용 증거 시각 |
| gpsData | event\_time에 GPS값 |
| received\_at | 서버가 해당 이벤트를 실제로 수신한 시각 (서버에서 자동 기록, 기기가 보내는 값 아님) |
| battery\_level | 배터리 잔량(%) — 선택 필드, 하드웨어 사양 확정 전이므로 추후 추가될 수 있음 |

**event\_time과 received\_at은 반드시 별도 컬럼으로 각각 저장되어야 합니다. 통신 음영지역 등으로 기기의 재전송이 지연되면 두 값에 차이가 발생할 수 있으며, 이 차이는 시스템 통신 신뢰도를 검증하는 근거 자료로 활용됩니다. 두 값을 하나로 통합하여 저장하지 않도록 유의해 주십시오.**

# **4. 필요 기능**

## **4.1 데이터 수신 API**

- HTTP REST and MQTT, JSON 포맷으로 이벤트 데이터를 수신하는 엔드포인트,
- 기기별 API 키 기반 인증 (기기 위변조·데이터 위조 방지)
- HTTPS 필수 적용

## **4.2 데이터 저장**

- 수신된 이벤트를 유실 없이 저장하는 데이터베이스
- device\_id, event\_time, gpsData(선택), received\_at, battery\_level(선택) 컬럼 포함

## **4.3 관리자 웹 대시보드**

- 관리자 로그인 (아이디/비밀번호 인증, 추후 계정 다중화 확장 가능하도록 설계)
- 위반 이벤트 리스트 화면 (기기ID, 발생시각 표시)
- 기간별·기기ID별 검색 및 필터 기능
- 리스트 CSV 다운로드 기능 (경찰·지자체, 공유PM업체 제출용)
- 기기별 최근 배터리 잔량 확인 화면 (정비 우선순위 파악용, 선택 기능)

## **4.4 인프라**

- AWS 등 관리형 클라우드 서비스 기반 구축
- 트래픽 증가 시 서버 재구축 없이 확장 가능한 구조 설계
- 도메인 연결 및 배포 포함

# **5. 비기능 요구사항**

| **항목** | **내용** |
| --- | --- |
| 현재 규모 | 파일럿 약 50대 기기, 동시 관리자 접속자 5명 이내 |
| 이벤트 발생 빈도 | 기기당 하루 수 회 수준 (대용량 트래픽 아님) |
| 확장성 | 추후 기기 수천 대 확장을 염두에 둔 설계 (단, 현 단계에서 과도한 설계는 지양) |

# **6. 산출물**

- 전체 소스코드 및 소유권 이전
- 배포된 서비스 URL (도메인 연결)
- 관리자 계정 및 사용 가이드
- 인프라 설정 정보 (클라우드 계정 접근 권한 포함)
- 하드웨어 자료 및 실물
