# PRD — IoT 안전발판 위반 데이터 수집·통합 관제

## 목표 / 담당 경계
장비 업체는 이동형 발판의 센서, LTE/LTE-M, RTC, GPS, 임시 저장, 네트워크 복구 시 자동 POST/재전송을 담당한다. 서버 개발사는 인증된 HTTPS POST 수신, 데이터 검증·저장, 운영자 웹, 검색, CSV, 지도, AWS 운영을 담당한다.

## 화면 정의
- SCR-01 로그인: ID/PW, 세션 오류 안내, 비밀번호 노출 방지
- SCR-02 통합 대시보드: 등록 기기 수/오늘 위반/최근 24시간 수신 기기/배터리 주의, 일자별 차트, 위반 위치 지도, 최근 이벤트
- SCR-03 이벤트 조회: 기간·장비 ID·수신 지연 필터, 페이징, 이벤트 상세, 지도 이동, CSV
- SCR-04 기기 관리: ID·상태·최근 수신·배터리·마지막 GPS·API Key 발급/회전은 별도 권한과 확인 절차
- SCR-05 지도 관제: 초기 전체 위반 위치 마커 + 클러스터; 기기 클릭 시 개별 이벤트/위치·경로만; 경로에는 '수집 지점 간 연결선' 표시
- SCR-06 통계/리포트: 기간별/기기별 위반 건수, 전송 지연 분포, CSV
- SCR-07 운영: API 실패율·저장 오류·백업 상태·감사/다운로드 이력

## 원 제안서와의 차이
원 제안서는 MQTT와 REST 모두 수신 요구를 포함하나, 현재 합의된 개발 가정은 **HTTPS REST only**. 최종 계약에 REST-only 명시하여 범위 합의 필요. `gpsData`는 원 제안서에서 선택 가능; 위치 경로·장비 찾기는 원 요구 범위를 넘어서는 별도 기능. `event_id`와 `event_type`도 원문에 없으므로 펌웨어 담당 협의 필요.

## 비기능
50대/관리자 5명 파일럿; 장기적으로 수천 대 지원; 관리형 또는 단일 EC2 초기 구축 후 단계 확장; DB 백업과 복구 확인; PII·위치정보 열람/보존 정책 별도 확정; 모바일은 네이티브 아닌 동일 반응형 웹앱.

## 검수 기준
- 등록 장비만 POST 성공, device ID/key 미일치는 거부
- 동일 이벤트 동시 재전송에도 정확히 1건; 원 최초 수신시각 불변
- 시간대 표시 Asia/Seoul, DB UTC-compatible timestamptz
- 위치 없는 이벤트는 표에 남지만 지도에서는 제외됨
- 1개 장비 선택 시 타 장비 경로 숨김; 전체 화면은 마커+클러스터 중심
- 모바일 360px 폭에서 수평 스크롤 강제 없는 주요 조회 흐름
- simulator / real API integration tests green, Docker repeatable, no secrets in repo
