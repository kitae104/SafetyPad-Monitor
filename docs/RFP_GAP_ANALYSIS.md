# RFP 대비 구현 현황 분석 (Gap Analysis)

- 기준 문서: `rfp/rfp.md` (IoT 안전발판 위반 데이터 수집 서버 및 관제 대시보드 구축 제안 요청서)
- 비교 대상: 현재 저장소 구현(백엔드 Spring Boot, 프런트 React, DB 마이그레이션 V1~V3, `docs/*`, `contracts/*`)
- 작성일: 2026-11-08
- 범례: ✔ 구현됨 · △ 부분 구현/조건부 · ✘ 미구현 · ➕ RFP에 없던 추가 구현

> 근거는 코드·문서 열람 기준입니다. AWS 실배포와 실제 장비 연동은 수행되지 않았으므로 "구현됨"은 로컬·에뮬레이터 검증 범위를 뜻합니다(`docs/ACCEPTANCE.md`).

## 2. RFP 항목별 구현 현황

### 2.1 데이터 흐름 / 전송 규격 (RFP §2, §3)

| RFP 요구 | 상태 | 구현 내용 / 비고 |
|---|---|---|
| 기기 → API → DB → 대시보드 흐름 | ✔ | `POST /api/v1/device-events` → PostgreSQL → 관리자 웹 |
| `device_id` | ✔ | 필수 필드 |
| `event_time` (기기 RTC, 초 단위) | ✔ | 타임존 포함 ISO-8601 필수, `timestamptz` 저장, 허용 구간(미래 10분/과거 366일) 검증 |
| `gpsData` | ✔ | 선택. `null`/생략/`""` 모두 "GPS 없음"으로 저장, 객체는 위·경도 범위 검증 |
| `received_at` 서버 자동 기록 | ✔ | 서버가 최초 수락 시 기록, 재전송으로 덮어쓰지 않음 |
| `event_time`/`received_at` 별도 컬럼 | ✔ | 별도 컬럼 저장. 지연(lag) 계산·`clock_skew_suspected` 표시까지 제공 |
| `battery_level` (선택) | ✔ | 선택 필드, 장비별 최근 값 화면 제공 |

| RFP 요구 | 상태 | 구현 내용 / 비고 |
|---|---|---|
| **4.1** HTTP REST 수신 (JSON) | ✔ | 400/401/403/413/415/422/429/503 오류 규약 정리 |

| **4.1** 기기별 API 키 인증 | ✔ | `X-API-Key`, 키↔`device_id` 불일치 시 403 |
| **4.1** HTTPS 필수 | △ | 운영 스택은 Caddy + Let's Encrypt 자동 TLS 구성. 실제 공인 도메인에서의 발급은 미검증(AWS/도메인 미확정) |

| **4.2** 지정 컬럼 포함 | ✔ | `device_id, event_time, gpsData, received_at, battery_level` + 추가 컬럼(§3 참조) |
| **4.3** 관리자 로그인 + 다중 계정 확장 | ✔ | 서버 세션/CSRF, 계정 다중화는 **이미 구현**(계정 추가·비활성화·비밀번호 초기화). 역할은 현재 `ADMIN` 1종 |
| **4.3** 이벤트 리스트 (기기ID, 발생시각) | ✔ | 데스크톱 표 / 모바일 카드, 상세 다이얼로그 |
| **4.3** 기간별·기기ID별 검색·필터 | ✔ | Asia/Seoul 달력 일 기준 필터 |
| **4.3** CSV 다운로드 | ✔ | UTF-8 BOM, 수식 주입 무력화, 최대 5만 행(초과 시 헤더로 표시), KST, 내보내기 감사 기록 |
| **4.3** 기기별 최근 배터리 화면 (선택) | ✔ | 장비 화면의 배터리 게이지, 20% 이하 주의(임계값은 가정치·설정 가능) |
| **4.4** AWS 등 관리형 클라우드 기반 구축 | △ | **배포 가이드(`DEPLOYMENT_AWS.md`)만 작성, 실행 안 함.** 현재는 사용자 Linux 서버에서 Docker Compose 운영 스택으로 검증 |
| **4.4** 서버 재구축 없는 확장 구조 | △ | 모듈형 모놀리스 + Docker, 1,000대 부하 시험(로컬). RDS 분리·다중 인스턴스 전환 절차는 문서화됐으나 미실행. 속도 제한이 인메모리라 다중 인스턴스 시 재검토 필요 |

## 5. RFP와 해석이 달라질 수 있는 지점

1. **MQTT**: REST와 병행 가능한 선택 기능으로 구현했습니다(기본 꺼짐). 기기 측 지원 여부와 운영 TLS 설정이 확인되기 전에는 REST가 기본 경로입니다.
2. **`event_id`**: RFP 규격에 없는 필수 필드입니다. 펌웨어가 못 주면 기기 재전송 중복을 서버가 완전히 막을 수 없습니다.
3. **"AWS 등 관리형 클라우드"**: 현재는 단일 호스트 Docker Compose입니다. 관리형 서비스(RDS, ALB 등) 사용은 확장 단계 계획으로만 기술돼 있습니다.
